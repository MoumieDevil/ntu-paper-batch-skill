# 三站路径与可观察故障

这里只使用当前页面实际提供的链接与控件。页面改版时重新观察，不依赖固定 CSS、全局序号或手拼下载 URL。

## IEEE Xplore

现有 NTU 会话标签页 → 检索 → 论文详情 → 官方 PDF/Download PDF → 完成下载 → 校验 → Zotero。

- 首先从详情页提取题名、按原顺序的作者、出版年份、会议/期刊、DOI、摘要和稳定 document 链接。
- 用户指定“用 Google/Chrome 插件”时，使用已有 Chrome 的扩展浏览器控制或可用的 Zotero Connector，不自行切换到系统鼠标控制。若随后明确授权用 Computer Use 处理“另存为”等原生窗口，可在工具允许且实际观察到该窗口时操作；权限拒绝则停下，不换途径绕过。
- PDF 按钮可能进入 `stamp` 包装页、查看器或新标签。先检查标签变化，再使用查看器提供的下载按钮。已实测的扩展分支是：普通 PDF 点击 → 检查实际包装页 DOM → 确认承载正文的 PDF `iframe` → 对该已观察到的元素调用扩展支持的下载操作（当前工具形式为 `locator('iframe').downloadMedia(...)`）。有多个 frame 时先定位准确目标，不能盲选。
- 以上是对页面现有 PDF 元素的下载，不是手工构造、猜测或重放 `stampPDF`、`ielx` 下载端点。对包装页链接直接调用下载可能超时，不代表权限失效；先观察是否出现查看器或“另存为”。仍需验证返回文件，不把点击或下载事件当成功。
- 也可在论文详情页通过 Zotero Connector 保存；完成提示后仍需核对目标集合和 PDF 子附件。只保存元数据不等于 PDF 成功。
- 普通 PDF 操作若显示无权限、订阅要求或登录阻断，记录事实并交给用户。页面上单纯存在 Personal Sign In 不是登录失效的证据。
- 会议论文用 `conferencePaper` / `proceedingsTitle`；期刊用 `journalArticle` / `publicationTitle`。不要把参考文献、SI、演示材料当正文。

## Web of Science

现有 NTU 会话标签页 → 主题检索 → Full Record → Full Text / View at Publisher → 出版社 PDF → 校验 → Zotero。

- WoS 通常是索引，不是 PDF 托管平台。不要在 WoS 页面无限寻找直接 PDF，也不要把索引访问权限等同于出版社全文权限。
- 结果数已出现但可见记录未加载时，可能是虚拟列表；可正常滚动结果区后重新观察，不据此认定无数据或登录失效。
- 保存 WoS 记录的题名、作者、来源、日期、DOI、摘要、WOS accession 和稳定 Full Record 链接；随后核对出版社文章是同一篇。
- 沿页面上的 Full Text、Publisher 或 DOI 链接导航，保留用户的浏览器会话。跳到出版社后先正常尝试 PDF，不预先要求再次登录。
- 如弹出新标签，接管新增的目标标签；原 WoS 页面不变不代表点击失败。
- 出版社与 WoS 出版年份等有实质冲突时，记录 online-first / issue 日期区别，不静默覆盖。元数据来源与 PDF 来源分别标注。
- 只在实际受阻时请求用户介入出版社权限。WoS 已登录并不保证所有出版社可下载。

## CNKI / 知网

现有 NTU 会话页面 → 主题检索 → 精确结果行右侧“下载/PDF下载” → PDF 校验 → 显式 UTF-8 元数据 → Zotero。

- 优先使用用户现有页面，不另找公共入口、不拼接 `crossids` 或代理参数。
- 下载前锁定结果行题名、作者、年份、期刊/学校、文献类型。行内操作不可用再打开详情页的官方下载控件。详情页的普通 Download 可能先展开 CAJ/PDF 子菜单，再点击明确的 PDF 链接下载；不能把 CAJ 改后缀冒充 PDF。
- 同一“下载”文字可能出现在排序栏、侧栏和多个结果行。以唯一题名所在行限定点击；不要使用整页 `.nth(n)` 猜测。
- 标题可能带零宽/BOM/双向格式字符：匹配时移除 Unicode 格式字符并规范空白，保留原始中文题名用于显示。JSON 使用 UTF-8；连续问号或替代字符出现时先修正元数据来源，不能以乱码写入。
- 学位论文用 `thesis`、`university` 和来源明确的 `thesisType`。没有 DOI 就保留空值，按题名+作者+年份去重。
- 来源实际提供不含会话签名的 `dbcode`、`dbname`、`filename` 记录链接时可保留；或使用已核实 DOI 的稳定链接。不要猜数据库名或拼造一个看似稳定的 URL。若只有带 `v=` 等签名的详情链接且确实没有稳定 URL，按[导入与恢复](import-and-recovery.md)使用 `--allow-missing-url` 和真实 `extra` 来源信息，Zotero 条目 URL 留空。
- 下载完成不保证文件通过严格解析。若 `inspect-pdf` 因重复 `/MediaBox` 等结构问题拒绝文件，保留失败记录并诊断，不自动改成宽松解析、重写 PDF 或跳过校验。仅针对重复且完全相同的根页面尺寸字段，可在用户明确同意保留原件、另建副本后，使用[有限副本修复](pdf-repair.md)并再次严格校验；其他情况保持阻断。不要把文件格式错误误报为机构权限或验证码问题。
- “AI 阅读/AI 下载”可能属于需要个人账号的另一产品。它不是普通下载失败后的免登录替代入口；出现个人登录要求即停在该入口，不调用其内部 reader/API。
- 拖入 PDF 后自动识别 DOI 仅为备选。无法识别时显式建立正确条目，再将该 PDF 挂到对应父项；不要不断重新拖入制造重复。清理已有条目需用户授权。

### “暂无数据”与验证：按证据判断

1. 看当前可见界面和错误；隐藏 iframe、离屏验证码模板不是正在阻挡操作的验证。
2. 检查检索是否打开新标签、是否限制了篇名/作者/子库/年份；不要同时重置全部条件而丢失用户意图。
3. 允许一次放宽：改用主题和一个核心词，去掉不必要的叠加限定；拿到结果再加年份/类型。逻辑语法依页面帮助，不将 `+` 等符号假定为所有知网版本通用。
4. 仍无结果如实报告，不推断封 IP。真实验证码先暂停下载，按下节处理；429、拒绝访问或个人登录提示则暂停该站并保留进度。

### 滑动拼图 / 识图点选：视觉尝试与交接

- 用户希望可行时由代理完成视觉验证。先观察当前页面与截图，确认验证确实正在阻挡本次正常操作；不要因隐藏模板存在就报验证码，也不要主动触发验证来测试。
- 只有当前工具支持该视觉交互、目标图像清晰可判定，并满足工具对**本次验证操作**的确认要求时，才通过页面正常滑块/点选控件尝试一次。泛泛的提前授权不能代替工具要求的当次确认；工具禁止时不能换低层接口绕过。
- 验证提交后重新观察：只有挑战消失并恢复正常目标页面，才继续一次正常下载。不能凭滑块已拖动或按钮已点击就称验证成功。
- 图像不清、题意无法可靠判断、控件不可操作、工具拒绝或一次尝试失败时，停止自动验证，请用户接管。checkpoint 记录“验证类型、可见现象、未完成原因、是否尝试过”，必要的截图仅保存在任务本地；不要反复刷新、穷举或重试。
- 不提取/注入验证 token，不重放内部验证接口，不调用第三方代解服务，不通过其他端点、账号、代理或关闭安全设置规避挑战。验证码完成也不证明论文全文权限或 PDF 文件有效，后续仍照常核验。
